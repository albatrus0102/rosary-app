# 성당 안 진본 창 대응표 (G-29)

걸어 다니는 3D 성당의 창 자리에 **그 성당의 실제 창 사진**을 건다. 표의 원본은 `assets/church/glass_placements.js`(`window.ChurchGlassPlacements`)이고, 이 문서는 그 근거다. 구현은 `SPEC.md §27`, 측정은 `PERF.md`.

## 규칙

- **진본만 진본 자리에.** 카탈로그(`glass_catalog.json`)의 `suggestedChurches[].use == "authentic"` 인 창만, 그 성당에만 건다. `reference`(같은 양식의 다른 성당 창)는 성당 안에 걸지 않는다. `glass_place.test.mjs` 가 이 규칙을 고정한다.
- 번들된 8점 가운데 7점이 걸린다. **`alabaster_slab`(라벤나 갈라 플라치디아 영묘의 석판)은 걸지 않는다**: 우리 성당 어디에도 진본 자리가 없다(카탈로그에서 네 성당 모두 `reference`). 감상실·갤러리에서만 본다.
- **왜곡 금지.** 사진 판은 언제나 사진 비율(`aspect_w_over_h`) 그대로다. 자리(개구부)와 비율이 다르면 **개구부를 사진 비율에 맞춰 다시 짓는다**(늘이거나 자르지 않는다). 원·타원 창은 사진의 알파 윤곽을 쓴다.
- 대응표에 없는 성당(라테라노·산타 마리아 마조레·명동·기본)은 건드리지 않는다(절차적 유리 그대로).
- `certainty`: `catalog` = 카탈로그 `location` 이 그 자리를 명시 · `literature` = 일반 문헌 지식(이 저장소에서 1차 자료로 확인하지 못함) · `assumed` = 같은 건물의 같은 종류 창이지만 정확한 자리는 모름.

## 정직하게 적어 둘 것

- **성 바오로의 64자리는 사진 2장의 반복이다.** 실제 창은 석판마다 무늬가 다르다. '이 창: 알라바스터 창 (1)' 칩은 "이 대성전의 창 사진"이라는 뜻이지 그 자리의 석판이라는 뜻이 아니다. 반복을 원하지 않으면 `glass_placements.js` 에서 그 슬롯의 `repeat` 를 지운다: 자리 번호가 `wins` 길이 안인 자리(각 슬롯의 첫 두 자리)만 사진이 되고 나머지는 절차적 알라바스터로 남는다(자리 수를 고정한 `glass_place.test.mjs` 도 함께 고친다).
- 성 바오로의 익랑 끝 창 4개·경당 위 창 4개·입구 벽 큰 창 3개는 그대로 절차적 유리다(비율·크기가 달라 이번에 손대지 않았다).
- 피렌체 드럼의 「주님 승천」 면 위치, 밀라노 창이 세 후진 창 중 어느 것인지는 **확인되지 않았다**. 1차 자료로 확인되면 표의 슬롯만 바꾸면 된다(빌더의 `ctx.glassPhoto('<slot>')` 호출 위치).
- 피렌체 정면의 양옆 오큘러스 2개와 드럼의 나머지 6개, 측랑·고창은 사진이 없어 절차적 유리 그대로다(번들 밖 창이 서버에서 오면 같은 방식으로 추가).
- 밀라노 사진의 세로 비율(1.75)은 카탈로그에서도 추정값이다. 창 전체가 아니라 부분이다.
- 사진은 1k(긴 변 1024px, webp q72)다. 드럼 창(지름 1.6m, 높이 21.6m)처럼 멀리 있는 창은 충분하지만, 밀라노 창(4.8m 폭)은 바로 앞에서 보면 1텍셀 ≈ 4.7mm 라 흐리다(카탈로그 limitations: 위쪽 단은 원본부터 흐림).

## 빌더에서 쓰는 법

```js
// 둥근 창·랜싯: 키트 창에 photo 를 넘긴다(자리·크기는 그 창 그대로)
ctx.rose({ ..., photo: ctx.glassPhoto('facade_center') });
ctx.window({ ..., photo: ctx.glassPhoto('aisle', j) });          // j = 자리 번호(반복 슬롯)
// 손으로 지은 창: 개구부를 ph.aspect 에 맞춰 짓고 자리를 알린다
var ph = ctx.glassPhoto('gloria');                               // {win, aspect, slot, index, shape} | null
if (ph) ctx.glassSlot({ photo: ph, x, y, z, face: [nx, nz], w, h, fallback: [mesh...], glows: [glowEntry...] });
```

`ctx.glassPhoto` 가 `null` 이면(대응표에 없음, `?photoglass=0`) 빌더는 예전 치수의 절차적 창을 짓는다.
