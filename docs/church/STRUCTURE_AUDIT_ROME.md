# 성당 구조도 대조 H-1 — 로마 4대 성전 (stpeter · lateran · maggiore · stpaul)

> 조사·대조 문서다. **이 단계에서 씬·앱 코드는 고치지 않았다.** 다음 단계의 구현자가 이 문서의 '수정 지시서'대로 고친다.
> 작성: 2026-11-15. 짝 문서: `STRUCTURE_AUDIT_OTHERS.md`(H-2, 나머지 성당).

## 0. 방법과 표기

**실제 구조** — 출처를 직접 열어 확인했다(§6 출처 목록에 '직접 확인'/'못 엶' 표시). 평면도는 섬네일을 내려받아 눈으로 보고, 축척 막대나 도면에 적힌 치수로 픽셀을 미터로 바꿔 쟀다(오차 ±1~2 m; '도면 실측'이라고 적은 값이 그것이다). 내려받은 그림은 scratchpad 에만 두었다.

**모델 측정** — 빌더를 Node(vm)에서 그대로 돌려 쟀다. Playwright·브라우저는 쓰지 않았다.
- `node tools/church_web/church_plan.mjs <id>` (이번에 추가): **걷기 지도**(충돌체로 막힌 칸 `#`, 걸을 수 있는 칸 `.`, 원형 충돌체 `o`, 높은 바닥 `^`, 좌석 `s`, 스폰 `S`, 촛불대 `c`) + 기둥 줄(같은 x 줄의 z 목록) + 큰 충돌체·높은 바닥 표. 실제 평면도와 '갈 수 있는 곳'을 견주는 도구다.
- `node tools/church_web/church_structure.mjs <id>` (H-2 작성): 키트 호출(제대·계단·바닥·궁륭 …)과 조형 bbox.
- `node tools/church_web/church_openings.mjs --all` (기존): 창 개구부 수.
- 그 밖의 치수는 빌더 소스의 상수(줄 번호를 적었다).

**단위** — '앱 m' = 실제 m × scalePercent/100. 좌표: 입구 +z, 제대 −z, 위 +y.

**판정** — 일치 / 허용(축척·단순화 감안) / **불일치-구조**(위상이 다름) / **불일치-비례** / 모델에 없음 / 실제에 없음(모델이 지어냄) / 의도적 축약.
**우선순위** — **P0** 눈에 띄는 구조 오류(평면 위상이 다름) / **P1** 비례·중요 설치물 / **P2** 세부. **작업량** — S(반나절 이하) / M(하루 안팎) / L(이틀 이상).

**네 성당 공통으로 구현자가 지킬 것**
1. 고칠 파일은 `assets/church/ch_<id>.js` 하나(+ 레이아웃을 바꾸면 `node tools/church_web/export_layouts.mjs` 로 `server/church/src/layouts.json` 갱신). 키트(`kit.js`)는 건드리지 않는다.
2. 고친 뒤 반드시: `node --test "tools/church_web/*.test.mjs"`(레이아웃·14처·전례·룩·창 배치 시험), `node tools/church_web/church_plan.mjs <id>`(걷기 지도에서 새 통로가 열렸는지, 막다른 틈이 없는지), `node tools/church_web/church_openings.mjs --check`(`data/glass_windows/<id>.json` 의 개구부 key·좌표가 그대로인지 — 창을 옮겼다면 그 JSON 과 `glass_placements.js` 를 같이 고친다).
3. CPU 가 한가해진 뒤: `node tools/church_web/shot.mjs <id> --pos x,z --yaw …` 로 지시서에 적은 지점의 전/후 화면, `node tools/church_web/e2e.mjs`. 콘솔 에러 0.
4. 성능 예산(BUILDER_API §5·§7.5): 정점 < 250k, 충돌체 < 300, 점광원 1개. 고치기 전후로 `__church.world.stats` 의 정점·메쉬 수를 적어 둔다. 새 조형은 기존 배치(`ctx.solid`, `ctx.surfBatch(...)`)에 넣어 draw call 을 늘리지 않는다.
5. 14처(`way_cross.js`)는 벽 후보에서 자리를 자동으로 고른다 → 벽을 뚫거나 옮기면 14처 자리가 바뀔 수 있다. `way_cross.test.mjs`·`stations.test.mjs` 와 `shot.mjs` 로 14처가 벽 안으로 들어가거나 새 개구부 앞에 걸리지 않는지 본다.
6. 전례 장식 기준점(`liturgy.js` 40~67행의 성당별 `altar`/`L`/`R`/`pots`)은 제대 좌표에 묶여 있다. 제대를 옮기면 같이 고친다(이 문서의 지시는 제대를 옮기지 않는다 — 예외는 따로 적었다).

### 2.4 수정 지시서 (lateran)

대상 파일: `assets/church/ch_lateran.js`.

**① 측랑 끝을 익랑으로 연다 (P0, M)**
1. 527~530행 '아케이드 끝벽'의 통짜 상자와 충돌체를 없애고, 같은 자리(z −5.9…−5.3)에 `wallOpen({ axis:'z', … wins:[…] })`(파일에 이미 있는 개구부 벽 도우미, 501행 용례)로 **한쪽에 아치 개구부 2개**를 낸다: 안쪽 측랑 중심 x = ±7.97(폭 2.6, 아치 정점 6.0), 바깥 측랑 중심 x = ±12.02(폭 3.0, 아치 정점 5.4). 개구부 사이·양옆 벽 조각마다 충돌체 AABB.
2. 개구부마다 계단 4단: `ctx.steps({ x0: c-1.3, x1: c+1.3, z0: -5.9, z1: -5.1, y0: 0, y1: 0.3, n: 4, dir: [0,-1] })`(신랑 계단 341행 근처와 같은 모양; 성 바오로 `ch_stpaul.js` 190행이 같은 처리의 본보기).
3. 바깥 측랑 쪽 익랑 구간(x 13.97…18.3)은 벽으로 남는다(지금 518행 충돌체가 z −5.9 까지 덮는다 — 그대로).
4. 아치 위 벽·코니스·창(593행 '앞벽 창')은 그대로 둔다. 아치 정점(6.0)이 측랑 궁륭 정점(7.8)·바깥 측랑 천장(6.2)보다 낮은지 확인.
5. 검증: 걷기 지도 −5.45 행에서 x ±8, ±12 칸이 `^`(계단)로 열려야 한다. `shot.mjs lateran --pos 8,0 --yaw 0`(안쪽 측랑에서 익랑 쪽), `--pos -12,-9 --yaw 180`(익랑에서 바깥 측랑 쪽).

**② 측랑 사이 기둥열 (P1, S~M)** — 492행 `ZP.forEach(…pil(…, zp, …))` 을 `ZP` 의 각 피어 **양 끝**(zp ± 1.5)으로 바꿔 한쪽 12개로(입구·익랑 끝의 것은 벽에 붙는다). 충돌체 반지름 0.4 유지. 521행 안쪽 측랑 돛형 궁륭은 `bays:[1,10]`(등간격) 대신 칸 경계를 새 기둥 z 에 맞춘다: `ctx.vault` 를 칸마다(길이 3.0 / 4.3 번갈아) 한 번씩 부르면 된다(정점 수는 같다). 바깥 측랑 평천장의 격자 방향 띠(`cofferBeams`)도 같은 z 에 맞춘다.

**③ 익랑 길이·안길이 (P1 + P2, M)** — `XT` 18.3 → **16.4**(62 m), `ZT0` −15.44 → −14.4. `XT` 를 쓰는 곳 전부(바닥판 2장, 익랑 끝벽·창 12개의 x, 오르간 x 17.3 → 15.4, 성체 제대 기둥 x −16.7 → −14.8, 충돌체)와 `layout.bounds`(x ±18.3 → ±16.4), `setCameraBounds`(x ±13.6 은 그대로)를 고친다. `ZT0` 는 성가대석 바닥·천장·벽(733행 `wallOpen` 의 u1, 567행 천장)과 후면 충돌체에 쓰인다. 좌석은 영향 없음. 익랑 창 12개가 옮겨지므로 `data/glass_windows/lateran.json` 의 transept 항목을 `church_openings.mjs lateran --json` 으로 갱신하고 `export_layouts.mjs` 를 돌린다.
   - 이 항목은 근거가 도면 실측 두 장(60 m, 66 m)과 "slightly further"라는 서술이다. 정확한 실측값을 새로 찾으면 그 값을 쓴다.

**④ 콘페시오 (P2, M)** — 제대·치보리오(655~716행)를 z −10.65 → −8.6(개선 아치 기둥 z −6.7 의 1.9 뒤)으로 옮기고, 콘페시오 난간(717행~)을 z −6.5…−4.4(신랑 바닥, 계단 앞)로 내려 신랑 계단 가운데(x ±1.9)를 콘페시오가 끊도록 한다(계단은 x ±1.9…±4.77 두 갈래로). 좌석 L/R 맨 앞줄(z −3.5)과 0.9 m 가 남으므로 **앞줄 1줄을 줄이거나**(128 → 120석) 좌석 origin 을 z −1.6 으로 민다 → 레이아웃 변경(서버 내보내기). `liturgy.js` lateran 의 `altar.z`·`L`·`R`·`pots` 를 같은 양(+2.05)만큼 옮긴다. 영향이 크므로 ①~③ 뒤에 한다.

**⑤ 성가대석 개선 아치·성문 (P2, S)** — z = `ZT0` 에 분홍 화강암 기둥 2개(646~650행을 복사: x ±4.27, 높이 5.8)와 아치 띠. 입구 벽 x = +12 문에 성문 표시(문 위 십자가 + 밝은 청동 패널).

**⑥ 코르시니 경당 (P2, M)** — 왼쪽 바깥벽 첫 칸(`ZB[0]` = 28.75)의 벽감을 실제 방으로: x −13.97…−19.5, z 25.5…32.0, 얕은 돔(`ctx.dome` r 2.4), 뒷벽 제대, 입구는 철창살(걷기 불가 유지 가능). `bounds` 를 넘으므로 출입 불가로 두면 레이아웃은 안 바뀐다.

### 2.5 고치지 않기로 한 것 (lateran)
- **후진 뒤 레오 회랑·제의실·박물관 입구, 북쪽 로지아 현관, 동쪽 현관**: 일반 신자 동선이 아니거나 실외다.
- **나머지 경당 8곳의 내부**: 벽감 + 제단화 색 면으로 둔다(실제도 철창살 너머로 본다).
- **신랑 길이 76 m(도면 71~75 m)·성가대석 깊이**: 오차 범위 안이다.
- **천장 높이 27 m**: 30 m/25 m 두 출처의 절충값(interiors/lateran.md §11) — 새 근거가 없어 유지.

### 3.4 수정 지시서 (maggiore)

대상 파일: `assets/church/ch_maggiore.js`. ①과 ②는 열주를 다시 놓는 일이 겹치므로 **한 번에** 한다(②를 먼저 정하고 ①의 좌표를 그 길이로 계산).

**② 신랑 길이 (P1, M) — 먼저 결정** — `Z_E` 34.4 → **28.2**(열주 구간 51.4 = 64.3 m). `NB`·`BAY` 로 계산되는 것(측랑 궁륭 칸, 고창 22, 측랑 창·벽기둥, 천장 격자 `CELLZ`)은 `NB = 19`, `BAY = 51.4/19 = 2.705` 로 따라간다(고창은 한쪽 11 → 10). `layout.bounds.z1` 34.2 → 28.0, `spawn.z` 29.5 → 24.5, 썸네일 카메라 `thumb.z` 23 → 19. 좌석(z −12…12.7)은 그대로. 정면 벽·문·성수대·바깥 풍경은 `Z_E` 를 따라 옮겨진다(546행~). 고친 뒤 `export_layouts.mjs`, `church_openings.mjs maggiore --json` 으로 `data/glass_windows/maggiore.json` 갱신.

**① 큰 아치와 대경당 (P0, L)**
1. 기둥 자리: `colZ(k)` 등간격 대신 §3.1 의 비율표로 놓는다 — `z = Z_A + f × (Z_E − Z_A)`. (② 뒤의 길이 51.4 기준으로 아치 구간은 z −13.0…−6.9, 중심 **z ≈ −9.95**.) 아치 양옆 안쪽 기둥(f = 0.198, 0.317)을 화강암(`GRANITE`)으로. `ionicColumn` 은 그대로 쓴다(충돌체 포함).
2. 들보(274~284행): 아치 구간에서 끊고, 그 자리에 반원 아치(`ctx.arch({ axis:'z', span: 6.1, y: 6.8 − …})` — 시작선은 기둥 꼭대기 5.5, 정점 약 8.5)와 아치 양옆 벽기둥. 아치 위 신랑 벽(모자이크 띠 구간)은 `openWall` 의 `holes` 에 아치 구멍을 더해 뚫는다(335~336행). 그 구간의 모자이크 패널·고창 1개는 없앤다(실제도 아치가 모자이크 띠를 잘랐다).
3. 측랑 외벽(400~405행 `openWall`): 같은 z 구간에 큰 아치 구멍(폭 6.1, 정점 5.8 — 측랑 궁륭 시작 `Y_AV` 6.0 아래). 그 구간의 측랑 창(`W_AISLE`)·곁 제대(`ALT` 의 해당 칸)는 뺀다.
4. 경당 방(502~544행 `chapel(sg, name)` 을 다시 짠다): 중심 (±21.2, −9.95), 그리스 십자 — 가운데 정사각 한 변 10.2(12.7 m) + 네 팔(깊이 3.4, 폭 7.0), 바닥 `cosmati`, 벽 다색 대리석 판, 가운데 위에 펜던티브 + 드럼(창 8, painted) + 돔(`ctx.dome({ r: 5.0, y: 11.0, rise: 5.0, drum:{…}, lantern:{…} })`). 걷기 가능(충돌체는 벽과 제대만). `layout.bounds` x ±11.98 → **±30.0**, `setCameraBounds` 도 같이.
   - 성능이 안 되면(정점 250k 초과·모바일 프레임 저하) 2단계 축약안: 가운데 정사각 + 돔만(팔은 얕은 벽감 1.2), `bounds` x ±24.
5. 설치물: 파올리나(−x) 바깥 팔 끝에 제단 — 푸른 청금석·금 틀 안에 성화 판(색 면: 짙은 금 바탕 + 성모자 실루엣). **이 성화는 묵주기도 앱에서 가장 의미 있는 자리이므로 조명(후광 `addGlow`)과 함께 가장 공들인다.** 양옆 팔에 클레멘스 8세·바오로 5세 무덤(흰 대리석 벽감). 시스티나(+x) 가운데에 성체 감실(금동 천사 넷이 받든 신전 모형: 원기둥 4 + 작은 돔, `mat:'metal'`) + `ctx.tabernacle` 의 성소등, 양옆 팔에 식스토 5세·비오 5세 무덤.
6. 촛불대: 지금 자리(−10.5, −5.4)는 새 파올리나 입구와 겹친다 → 왼쪽 측랑 벽 z = +3.0 으로 옮긴다(`face [1,0]` 유지) → 레이아웃 변경, `export_layouts.mjs`.
7. 기존 얕은 경당 방(z −19.5…−13.5)과 그 충돌체(x ±12.2…±18.4)는 없애고 측랑 외벽을 그 구간에 다시 잇는다(성소 옆은 실제로 벽이다).
8. 검증: 걷기 지도에서 (0, −9.95) → (±9.5, −9.95) → (±21, −9.95) 가 `.` 로 이어져야 한다. `shot.mjs maggiore --pos 0,2 --yaw 0`(신랑에서 양쪽 큰 아치가 보이는지), `--pos -9.5,-9.95 --yaw 90`(측랑에서 파올리나 제단), `--pos 21,-9.95 --yaw 0 --pitch 40`(시스티나 돔).
9. 14처·전례: 14처가 측랑 벽 그 구간에 걸려 있었다면 자리가 바뀐다(`way_cross.test.mjs`). 전례 기준점(제대 z −21.2)은 그대로.

**③ 문 (P2, S)** — 550행 `entHoles` 에 좌우 문 2개(u = ±4.2, 폭 2.0, 높이 3.4)를 더하고 닫힌 청동문 상자를 단다. 그 위 고창(9.6)과 겹치지 않는다.

**④ 개선 아치 뒤 (P2, S~M)** — 개선 아치 개구 반폭 `ARC_A` 4.6 → 5.4(13.65 m × 0.8 / 2 = 5.46), 후진 반지름 `AR` 5.6 → 5.4 로 맞추고, '익랑' 바닥·천장(245·389행)의 x 범위를 ±12.2 → ±5.6 으로 줄여 양옆을 벽으로 닫는다(740행 `openWall` 은 그대로). 개선 아치 모자이크 질감(600행 `triTex`)의 아치 반경도 같이.

**⑤ 프란치스코 교황 무덤 (P2, S)** — 왼쪽 측랑 외벽, 새 파올리나 입구의 입구 쪽 옆(z ≈ −4.5)에 낮은 벽감(폭 1.6, 높이 2.2): 흰 대리석 판 + 십자가 부조 색 면. 글자는 넣지 않는다.

### 3.5 고치지 않기로 한 것 (maggiore)
- **스포르차·체시(마시모) 경당, 세례당, 십자가 경당, 제의실**: 측랑 벽의 문·곁 제대로 둔다. 큰 경당 2곳을 제대로 짓는 것이 먼저다.
- **성소 단 출입**: 실제로도 올라가지 않는 곳 — 출입 불가 유지.
- **정면 현관·로지아·종탑**: 실외.
- **기둥 높이**(모델 6.9 m): 실측 출처를 찾지 못했다. 유지.

### 4.4 수정 지시서 (stpaul)

대상 파일: `assets/church/ch_stpaul.js`. 구조 오류(P0)는 없다.

**① 고창을 하나 건너 하나로 (P1, S~M)** — 신랑 고창을 짓는 반복(210행 `YM`/`YT` 근처의 `wrun`/`win` 호출)에서 짝수 칸만 창으로 두고 홀수 칸은 금 틀 그림 판(성 바오로 생애 프레스코 대역: 따뜻한 색 면, `wallFace` 또는 색 상자)으로 바꾼다. 양 끝 칸은 반 칸이므로 그림 판. 측랑 창(한쪽 11)은 그대로. 사진 창 대응표(`glass_placements.js` 27행 `clerestory`, `repeat: true`)는 개수가 줄어도 동작하지만 `church_openings.mjs --check` 가 key 불일치를 낼 것이므로 `data/glass_windows/stpaul.json` 을 다시 만든다. 낮 시간대 신랑 밝기가 떨어지면 `looks.js` stpaul 의 `ambK` 를 0.8 → 0.9 로.
   - 근거가 '외관에서 센 창 수(PDF)'와 '절반을 막았다(fr.wikipedia, 기존 조사서 인용)' 두 가지다. 실내 사진으로 한 번 더 확인한 뒤 고친다(공식 가상 순례 `vatican.va/various/basiliche/san_paolo/vr_tour/`).

**② 콘페시오 (P2, S~M)** — 643~650행: 검은 판을 없애고 x ±1.7, z −16.3…−14.3 을 y = −0.9 까지 내려앉은 구덩이로(옆면·바닥 상자, 마조레 `ch_maggiore.js` 656~660행이 본보기), 양옆에 내려가는 계단 2줄(보기만; 충돌체로 막음), 난간은 흰 대리석. 가운데 계단(189행 `ctx.steps` x ±5.35)은 콘페시오 폭만큼 가운데를 비워 두 갈래로. 콘페시오 네 귀에 설화석고 기둥 4개(높이 3.2, `color 0xe8d9b0`, `mat:'gloss'`, 위에 아무것도 없음).

### 4.5 고치지 않기로 한 것 (stpaul)
- **길이 6 % 초과**: 131.66 m 를 내부 길이로 쓴 결과다. 기둥 수·칸 수·비례 인상은 맞고, 줄이면 좌석·창 64개·사진 슬롯·서버 레이아웃이 모두 움직인다. 이득이 작다.
- **사면 회랑(실외)**: 걷는 영역 밖이고, 넣으려면 70 m 상한 때문에 축척을 53 → 35 % 로 내려야 한다. 가운데 문 밖으로 '보이기만 하는' 회랑을 짓는 방안은 질문 2.
- **후진 옆 경당 3곳·세례당·수도원 회랑**: 문 뒤의 방 — 벽 개구부로 둔다.
