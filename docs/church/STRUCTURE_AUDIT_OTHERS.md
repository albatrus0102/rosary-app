### 0.1 방법

- **실제**: 평면도·단면도 이미지를 내려받아 직접 보고 쟀다(스그릴리 1733년 피렌체 실측 판화 3장, TCI 2005 밀라노 평면도, 명동 실내·정면 사진 9장 — 전부 위키미디어 공용, 저장소에는 넣지 않음). 글 출처는 위키백과 각 언어판·공식 사이트·현장 안내판. 직접 열지 못한 것은 §6.2 에 적었다.
- **모델**: 빌더 소스를 읽고, 새 조회 도구로 빌더를 Node 에서 그대로 돌려 쟀다.
  - `node tools/church_web/church_structure.mjs <id>` — 평면 범위·지은 조형의 경계 상자와 최고 높이·좌석·제대/독서대/감실/성상/성수대/계단/단/궁륭/등 호출 목록. `--calls` 전부, `--json`, `--all`.
  - 창은 기존 `tools/church_web/church_openings.mjs`(E-3), 밀라노 창은 `milan_openings.mjs`.
  - 한계: 빌더가 키트 도우미를 거치지 않고 배치에 직접 넣은 조형(피렌체의 벽 패널, 명동의 slab, 밀라노의 기둥 템플릿)은 호출로 잡히지 않아 소스의 상수로 확인했다.
- 좌표는 모든 성당 공통: 입구 +z, 제대 −z, 위 +y. 단위는 앱 m(= 실제 m × scalePercent/100).
- **이 단계에서 Playwright 화면 확인은 하지 않았다**(지시). 아래 판정은 소스·수치·도면 대조다. 구현자는 고친 뒤 `shot.mjs` 로 반드시 눈으로 확인한다.

### 1.4 수정 지시서 (순서대로)

건드릴 파일: `assets/church/ch_florence.js`(주), `tools/church_web/church_openings.mjs`(어댑터의 트리부나 key), `data/glass_windows/florence.json`, `docs/church/GLASS_ALL_CHURCHES_PLAN.md` §1(개구부 표), `assets/church/liturgy.js`(제대·독서대 좌표는 안 바뀌므로 확인만).

**A. 큰 아치와 트리부나 높이 + 윗창 15개 (F1·F2 + E-3 의 F5) — 한 번에**
1. `:43` `Y_BIG = 12.6, R_BIG = 4.9`. (`A_BIG` 3.75 유지.)
2. 팔각 면 루프(`:482-507`): k 짝수 면에서는 발코니 띠 2개(`:496`, `:498`)와 까치발(`:505`)을 만들지 않는다(아치 정점 17.5 가 띠 13.15~13.95 를 지나감). 드럼 아래 돌림띠(18.4~18.9)는 그대로 — 아치 정점 17.5 + 아치띠 0.5 = 18.0 < 18.4 인지 확인하고, 닿으면 `R_BIG` 를 4.6 으로.
3. `tunnel()`(`:467-477`)은 상수만 따라간다. 터널 문설주 면에 `Y_BAL − 0.35` 띠를 한 줄 넣어 팔각의 발코니와 이어 보이게 한다.
4. `tribune()`(`:609-653`): 벽이 12.6 까지 올라간다. 경당마다 `archedWall(F, {… top: YS …})` 에 `holes: [holeLancet(0, 8.45, 0.86, 2.2)]` 를 넣고, `reveal(F, 구멍, 0.6)` 과 `ctx.window({ x·z = B(0, −0.45), y: 8.6, face: [nx, nz], w: 0.86, h: 2.05, top: 'pointed', pattern: 'lancet', colors: GLASS, seed: 300 + k*10 + i, beam: false })` 를 더한다. 경당 천장(`AH` 5.6) 위 뒤쪽이 비어 보이지 않게, 윗창 뒤(d −0.6)에 어두운 뒷판 없이 유리만 둔다(다른 창과 같은 방식).
5. 트리부나 다섯 면에 `YS − 0.35` 발코니 띠(폭 = 변 길이, 깊이 0.36) + 까치발 3개씩.
6. 꼭짓점 벽기둥(`:514-524`)의 상부 몸통은 13.5 까지 그대로 둔다(아치 기공 12.6 과 0.9 겹쳐 주두처럼 보임).

### 1.5 고치지 않기로 한 것

- **고정 신자석·촛불대 자리**: 실제에는 고정 신자석이 없지만 앱의 앉기·촛불 기능 자리다.
