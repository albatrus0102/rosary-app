# 성당 카메라: 벽을 개의치 않는 3인칭 + 잘라내기(cutaway) + 손맛 (2026-11-23 3차)

> 작성: Claude Opus 5.5. 구현 `assets/church/cam_guard.js`(`createCut`·셰이더 `patchSee`·`build`), `assets/church/controls.js`(`FEEL`·`stepLook`·`createFollow`·`moveStep`·`shapeJoy`·`followStep`),
> `main.js updateCamera`·`updateMe`, `world.js`(잘라내기 바탕), 앱 `lib/church/church_hud.dart`(「시점」 단추·손잡이)·`lib/app/settings.dart`(`ChurchCamView`).
> 3인칭 리그의 예전 설계(벽에 맞춰 당기던 것)는 [CAMERA.md](CAMERA.md) — 지금은 쓰지 않는다.

## 왜 바꿨나

2차(같은 날 앞서)는 「좁으면 자동 1인칭 + 벽에 맞춰 거리를 줄이는 스프링 암」이었다. 실기기에서 아시시를 해 본 사용자:

> 「그냥 뷰를 벽을 개의치 않고 보여주면 안 되나? 촬영하는 쪽에 벽이 있는지 없는지는 사실 의미 없잖아. 보여지는 쪽만 충실하면 될 거 같은데. 다른 앱들도 다 그렇게 하지 않나? 그러면 1인칭도 굳이 쓸 필요가 없고. 아시시를 해 보니 아직도 덜컹거리는 곳이 좀 있더라고. 그리고 1인칭이 컨트롤이 까다로워서.」

그리고 덧붙여: 「하는 김에 좀 더 부드럽고 고급스럽게(떼면 천천히 멈추는 등) 고민해서 더 반영해, 진짜 게임처럼」. 웹 데모를 본 뒤에는 「위에서 거의 바로 내려다보는 기본 구도 말고 게임처럼 뒤에서, 신랑·벽·제대가 보이게」.

그래서 심즈·인형집 보기·가림물을 지우는 3인칭 게임처럼 **카메라는 충돌하지 않고, 카메라와 아바타 사이(카메라 쪽)의 가림물을 지운다.**

## 1. 카메라: 충돌 없음

- 카메라 = 부드러운 피벗(아바타 가슴, 임계 감쇠 스프링) + **사용자 각도(yaw·pitch)·거리 그대로의 팔**. 벽·천장·기둥이 카메라를 밀거나 당기지 않는다 — 튐·덜컹거림의 원인(거리 갱신·시점 바꿈·벽 속 탈출)이 없다.
- 없앤 것: 리그(`createRig` 스프링 암·자동 시점 올리기/돌기/내리기·카메라 컷), 자동 1인칭(`createView`), 카메라 공간 복셀(`buildSpace`)·층 칸막이·벽 속 탈출, `main.js` 의 벽 당기기(`clipWide`). 카메라 높이를 바닥·상자 천장으로 자르던 것도 없앴다(계단에서 팔 길이가 바뀌었다).
- 남긴 구도: 앉기·무릎 꿇기 시점(앞옆 45°, `prayYaw` 가 앉을 때 한 번 가림이 적은 쪽을 고른다), 기도 자리 도착 시점(`SPOT`), 좁은 회랑의 사진 창 감상(`camReach`) — 모두 사용자가 고른 장면의 구도이고, 그 사이의 가림물은 잘라낸다.
- 기본 구도(`FEEL.boomDist` 5.0m · `pitchDefault` 0.2rad · `lookDrop` 0.25m): 카메라는 발 위 약 2m(머리 조금 위), 시선은 약 14° 아래. 아바타 뒤에서 신랑·벽·제대 쪽을 본다. 예전 기본(7.2m · 26°)은 카메라가 발 위 4.1m 라 화면 대부분이 바닥이었다. 핀치 범위는 그대로(× 0.55~1.6).

## 2. 잘라내기(`cam_guard.js createCut` + 셰이더)

모든 성당 메시(벽·천장·기둥·창·의자·가산 혼합 등빛, 아주 작은 장식 면 포함)에 꼭짓점 값 두 개를 단다 — `seeThru`(칸) · `seeLvl`(그 면이 놓인 층의 바닥 높이, 0.25m 단위). 셰이더는 균일값 다섯(`uSeeA` 카메라 · `uSeeB` 가슴 · `uSeeK` · `uSeeP` · `uSeeQ`)만 보고 조각을 디더로 지운다 — **합친(batched) 메시도 조각 단위**, 재질 복제·재컴파일·추가 그리기 패스·draw call 증가 없음.

| 칸(seeThru) | 무엇 | 지우는 것 |
|---|---|---|
| 255 가는 면 | 홀로 선 기둥·피어·성상 | ①②③④ |
| 212 가산 혼합 빛 | 빛줄기 판·등빛(바닥 빛 웅덩이는 빼고) | ① 3인칭이면 늘 ②③④ |
| 170 넓은 면 | 벽·아치·천장·윗벽·창, 아주 작은 장식 면(벽 등·까치발) | ①②③④ |
| 85 낮은 물체 | 의자·무릎틀·난간 | ①(앉았을 때)②③④ |
| 42 바닥 | 걷는 바닥·단·위층 바닥 판 | 머리 위(발 + 1.2m)면 ①②, ④ |

1. **원뿔**: 카메라 → 아바타 가슴(반지름 카메라 쪽 0.3R → 아바타 쪽 R, R = 거리 × 0.22, 1~2m). 가슴·머리 선이 면을 지나면 켠다.
2. **카메라 둘레**: 카메라에서 0.7m 안(near 평면 바로 앞의 면 조각·반쪽 가구가 화면을 덮지 않게). 3인칭이면 늘.
3. **인형집 단면**: 카메라가 아바타 방 밖이면(가슴·머리 선이 넓은 면을 지난다) 아바타에게 **가장 가까운 카메라 쪽 벽 면**에서 0.3m 카메라 쪽(최소 0.5m)에 세운 세로 평면보다 카메라 쪽의 벽·기둥·가구를 지운다 → 방을 들여다본다. 아바타 앞·옆 가구는 남는다.
4. **위층**: 아바타 발보다 1.2m 넘게 높은 첫 층 바닥 아래 1.3m(판 두께)까지 카메라가 오르고, **그 층 면이 정말 아바타를 가릴 때만** 그 층(바닥 − 0.3m 위의 `seeLvl`)을 아바타 앞 첫 벽 + 1m(먼 평면)까지 지운다. 계단 우물처럼 위층 바닥의 구멍으로 보이면 지우지 않는다(우물 둘레 바닥이 그대로). 여러 층 성당(아시시·여의도동)만 — 층마다 보이기(`levelVis`)는 그대로 쓴다.

- **깜빡임 막기**: 켜기는 바로(0.08초에 녹아 사라짐), 끄기는 조건이 0.4초(카메라가 초당 2m 넘게 움직이는 동안은 1초까지) 이어진 뒤 0.15초에 돌아온다. 0.35초 뒤 카메라 자리(지금 속도)도 미리 보고, 막히면 미리 켠다. 켠 채로 둘지는 0.7초 뒤 자리까지 본다. 단면 자리는 시간 상수로 옮긴다(다가올 때 0.05초, 물러날 때 0.15초).
- **잘라내기 바탕**(`world.js`, 여러 층만): 위층·단면을 지운 동안, 아바타가 맨 아래층(아시시 묘소·여의도동 1층 로비)이면 카메라를 둘러싼 흙빛 둥근 막(반지름 150m, 모든 면 뒤·하늘 앞), 그 위층이면 맨 아래층 바닥 0.25m 아래 흙빛 판(안개 없음)을 그린다 — 방 밖(모델이 없는 땅속)이 하늘로 비지 않게. 평소 draw call 0, 켜진 동안 +1.
- 반사 탐침 굽기 동안은 `see.mute()/unmute()` 로 모두 끈다(`probe_fx.js`). 그림자 패스는 잘라내지 않는다(실내 빛·그림자 그대로).

값(`CUT`, `cam_guard.js`): `coneMin/Max/K` · `headClear` 1.2 · `nearR` 0.7 · `fadeIn` 0.08 · `fadeOut` 0.15 · `hold` 0.4 · `holdMove` 1.0 · `moveV` 2.0 · `lead` 0.35 · `planeBack` 0.3 · `planeMin` 0.5 · `upperAbove` 1.2 · `upperMargin` 1.3 · `upperKeep` 0.3 · `farMin` 3 · `farPad` 1.0.

## 3. 「시점」 단추: 뒤에서 보기(기본) ↔ 1인칭

- 자동 1인칭은 없다. 1인칭은 단추로 고를 때만(0.5초에 눈으로 들어간다, 앉기·기도 중에는 기도 시점).
- 저장: `AppSettings.churchCamView`(키 `church_cam_view`, `follow|firstPerson`). 예전 저장값 `auto`(자동)는 **뒤에서 보기로 읽고 저장값도 고친다**(백업·다른 기기에도). 백업 등록부 설명 「카메라 시점(뒤에서 보기·1인칭)」.
- 웹: `ChurchAPI.setViewMode({mode: 'tp'|'fp'})`(예전 `'auto'`·모르는 값 → `tp`). 웹 데모 껍데기(`web_demo/shell`)도 뒤에서 보기 ↔ 1인칭.
- 320dp 폰 도구 줄: 항목 수는 그대로(소리·아바타·인사·시점·가기) — `ChurchTopActions.compactFor` 그대로 48dp.

## 4. 손맛(`controls.js FEEL` — 휴대폰에서 써 본 뒤 고칠 값은 모두 여기)

모든 감쇠는 dt 기반 지수식(`exp(−dt/τ)`, 임계 감쇠 스프링의 닫힌 꼴, 걷기 이동은 지수식의 정확한 적분)이라 30·60·120Hz 에서 같다. 긴 프레임은 `main.js` 가 dt ≤ 0.05초로 자른다.

| 값 | 기본 | 뜻 |
|---|---|---|
| `boomDist` · `pitchDefault` · `lookDrop` | 5.0m · 0.2rad · 0.25m | 기본 구도(위 1절) |
| `lookVelTau` | 0.05초 | 끄는 동안 각속도를 고르게 재는 시간 |
| `lookFriction` | 0.12초 | 손을 뗀 뒤 관성 감쇠(초당 2rad 로 뗐으면 약 0.45초에 멈추고 0.24rad 더 돈다) |
| `lookStop` · `lookMaxYaw` · `lookMaxPitch` | 0.04 · 5 · 2.5 rad/s | 멈춤 문턱(거의 멈춘 채 떼거나 탭이면 바로 선다) · 튕김 상한 |
| `pitchMin/Max` · `lookSoft` · `lookEdgeTau` | 0.06/1.25 · 0.15 · 0.04 | pitch 범위와 탄성 끝(끝 0.15rad 안에서 속도를 더 죽여 부드럽게 선다) |
| `zoomOmega` | 12 | 핀치 목표로 따라가는 임계 감쇠 스프링(약 0.3초에 95%, 넘치지 않음) |
| `followOmega` · `followOmegaY` · `followSnap` | 9 · 12 · 1.5m | 피벗 따라가기(걷는 중 늦음 2v/ω ≈ 0.3m, 넘치거나 출렁이지 않음) · 순간 이동 |
| `recenter` · `recenterIdle` · `recenterWalk` · `recenterRate` · `recenterRamp` · `recenterCone` · `recenterSpeed` | true · 2초 · 1초 · 0.45/s · 1.5초 · 1.2rad · 0.6m/s | 자동 뒤로 맞추기: 2초 안 만지고 앞쪽으로 1초 넘게 걸으면 아주 천천히(1.5초에 걸쳐 세짐). 끄려면 `recenter: false`. 관성으로 도는 동안은 쉰다 |
| `moveAccelTau` · `moveDecelTau` · `moveStop` | 0.12 · 0.075초 · 0.02m/s | 출발(0.3초에 92%) · 손잡이를 놓으면 약 0.32초·0.1m 미끄러지듯 선다(더 늘리면 멈추는 동안 디딘 발이 미끄러진다 — gait.test 5% 한도: 0.08 에서 5.0%) |
| `turnRate` · `autoWalkRate` | 9/s · 12/s | 몸 돌리기 · 누르기 이동의 속도 맞춤(길을 따라가야 해서 예전 그대로) |
| `joyDead` · `joyLinear` | 0.12 · 0.35 | 손잡이: 가운데 0.12 는 0, 그 밖은 0..1 로 다시 펴서 `0.35u + 0.65u²`(가운데 근처는 천천히 정확하게) |
| `fpBlend` | 0.5초 | 1인칭으로 들어가고 나오는 시간 |

- 앱 손잡이(`ChurchMoveZone`): 놓으면 손잡이가 `knobReturn`(180ms, easeOutCubic)에 가운데로 돌아온다. 죽은 구역 0.12 는 앱·웹 같은 값.
- 걸음(다리)은 실제 이동량을 따르므로 가속·감속을 그대로 따라간다(avatar.js 는 고치지 않았다). `gait_lib.mjs` 의 걷기 흉내도 같은 `moveStep` 을 쓴다(시험의 손잡이 값은 속도 비율이라 곡선은 뺐다).

## 숫자

헤드리스 카메라 표본(`node tools/church_web/cam_sim.mjs`, 예전은 `--old <고치기 전 cam_guard.js>`): 아시시 묘소(둥근 방 8곳·기도방·층계참)·묘소 계단·하부 → 상부 계단, 여의도동 곡선 계단·성가대석 아래, 명동 성단 옆 측랑, 밀라노·성 바오로 주보랑, 각 성당 트인 신랑. 자리마다 네 방향에서 1초 서 있다가 5초 동안 초당 1.4rad 로 돌리고(한 바퀴 넘게) 2초 동안 위아래로도 끈다. 걷기 경로 6개 더. 모두 67,106 프레임(1/30초). 예전은 그때의 기본 구도(26°·7.2m), 지금은 새 기본 구도(11°·5m).

지표(3인칭 프레임): **튐** = 한 프레임 카메라 이동이 (피벗 이동 + 팔 × 각도 변화)보다 0.35m 넘게 큼 · **입력 없는 거리** = 사용자가 거리를 안 바꿨는데 카메라 → 피벗 거리가 1cm 넘게 바뀐 프레임 · **가림** = 카메라 → 머리·가슴 두 선이 모두 지우지 못한 면에 막힘(몸 반지름 0.3m 앞까지, 가림 일부 = 둘 중 하나) · **깜빡** = 잘라내기가 켜졌다 꺼졌다 하는 한 구간이 0.3초보다 짧음 · **1인칭** = 아바타가 안 보이는 프레임 · **µs** = 카메라 계산(JS) 프레임당.

## 남은 것

- 실기기 손가락 느낌(관성 마찰·줌 스프링·자동 뒤로 맞추기의 세기)과 보통 화질 프레임 시간은 헤드리스로 잴 수 없다 — 위 `FEEL` 표의 값을 써 보고 고친다.
- 카메라가 낮아져(발 위 약 2m) 아시시 상부 신랑에서 정면 장미창 쪽을 보면 간단 화질의 빛줄기가 화면을 하얗게 덮는 칸이 있다(확인 샷 신랑 6번째 칸). 잘라내기 문제가 아니라 빛줄기 세기·구도 문제라 손대지 않았다.
- 카메라 쪽 벽을 지운 자리 너머(건물 밖)는 단층 성당에서는 하늘·땅, 여러 층 성당은 흙빛 바탕이 보인다. 인스턴스 메시(촛불)·사람(배경 신자)은 지우지 않는다(작고, 아바타를 가리면 금색 실루엣이 보인다).
- 카메라가 벽 속에 서 있는 동안 near 평면(0.3m) 안쪽은 카메라 둘레 잘라내기(0.7m)가 지운다. 이 반지름을 키우면 벽 가까이에서 둥근 구멍이 화면 가장자리에 보인다.
