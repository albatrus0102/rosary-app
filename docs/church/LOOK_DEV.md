# 성당 룩 개발(조명·재질·분위기) — 진단·프리셋·재질 (2026-11-14)

사용자 불만: 다른 가상 성당 앱('평화의 대성당')과 같은 성 베드로 제대 부근을 비교하면 "퀄리티 차이가 너무 난다".
참고 화면은 **영감만** 얻었다(모델·텍스처를 가져오지 않음). 이 문서는 진단 → 룩 프리셋 → 재질·지오메트리 → 성능 예산 순서다.
성능 수치는 [PERF.md](PERF.md) §2026-11 최적화·룩, 브리지·데이터 형식은 [SPEC.md](SPEC.md) §34.

## 1. 진단: 우리 성 베드로 vs 참고 화면

비교 화면: 우리 `docs/ux/screens/3d_stpeter_walk.jpg`, 헤드리스 `look_dev/before/stpeter_*`(360×800, 11·18.3·22시) ↔ 참고 제대 부근 2장, 측랑·광장 3장.

결론: 격차의 대부분은 **모델이 아니라 조명 비율(앰비언트·환경광 과다)과 톤(대비·비네트·블룸)** 이다. 이것은 텍스처 없이 값만으로 줄일 수 있다.
지오메트리 디테일(꼬인 기둥)은 대표 요소 하나만 보강했다.

## 2. 룩 프리셋(`assets/church/looks.js`)

성당 id 마다 값 묶음. `world.js` 가 시간대 키프레임(KEYS)을 뽑은 뒤 **곱하거나 섞고**, `render.js` 가 걷기 프로필의 최종 패스·블룸에 쓴다.
`night` 안의 값은 밤 정도(`env.night` 0..1)로 선형 보간한다. 정하지 않은 값은 `DEFAULT`(= 예전 화면과 같은 값)이므로 프리셋이 없으면 화면이 바뀌지 않는다.
**사진 창 화소는 어떤 룩에서도 보정·톤매핑·블룸·AO 를 받지 않는다**(알파 0 경로, G-29) → 창 색 불변.

**현재 기본 적용은 성 베드로뿐**이다. 나머지 성당 값은 `DRAFTS`(초안, `?looks=all` 로만 적용)이며 화면 검증 뒤 옮긴다(LOOK_DEV_HANDOFF.md).
키 전체 목록과 뜻은 `looks.js` 머리 주석, 결합 규칙은 SPEC §34.

- **시간대·밤·햇빛 모드와의 결합**: 프리셋은 KEYS 위에 얹는 배율이라 해 경로·빛줄기 방향·밤 전환은 그대로 따라간다. 감상 모드(사진 창 감상, 'view' 프로필)에서는 적용하지 않는다(`env.grade = null` → 예전 값).
- **화질 단계**: high 는 전부, mid 는 블룸 세기 × `midBloomS`(0.8)·SSAO·바닥 반사 없음, low 는 후처리가 없어 노출·조명 배율만 적용된다(대비·비네트·블룸 없음).
- 전례 장식(liturgy.js, 제단 보 색 등)과는 독립이다.

## 3. 재질·지오메트리

## 5. 남은 격차(다음 단계 후보)

- 참고 앱은 가로 화면·낮은 카메라로 제단을 크게 잡는다. 우리 세로 화면은 아바타 뒤 7m 라 제단이 작다(카메라 범위는 조작·HUD 와 함께 정할 일).
- 제대 위 촛대·금박 요소는 기존 `ctx.altar(candles:4)` 그대로다. 촛대 형태(받침·마디)는 다음 단계.
- 벽 석재의 줄눈·미세 변조는 사진 질감(tex_pack) 해상도에 묶여 있다. 새 질감 없이 더 하려면 절차적 AO 줄눈(데칼)이 필요하다.
- 실기기 화면(OLED·밝기 자동)에서는 어두운 부분이 더 어둡게 보일 수 있다. 실기기에서 `expK` 를 확인할 것.
