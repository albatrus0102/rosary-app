### 0.2 조회 스크립트 `tools/church_web/church_openings.mjs`

```
node tools/church_web/church_openings.mjs --all              # 일곱 성당 요약(개구부 수·구역·좌표계)
node tools/church_web/church_openings.mjs florence           # 개구부 전부(구역별, world 좌표·yaw·크기·형태·지금 유리)
node tools/church_web/church_openings.mjs florence --json    # 구현용 JSON
node tools/church_web/church_openings.mjs florence --md      # 이 문서의 표(같은 치수는 한 줄로 접음; 전부는 --md-full)
node tools/church_web/church_openings.mjs --check            # data/glass_windows/*.json 의 key·좌표가 지금 빌더와 맞는지
```

- `milan_openings.mjs` 와 같은 방식(가짜 canvas + vm)으로 빌더를 그대로 돌린다. 성당마다 창을 짓는 방법이 달라 **세 갈래**를 모은다: (1) 키트 창 `ctx.window`/`ctx.rose` 의 사양(`S_.windows`/`S_.roses`; 돔 드럼 창 포함) (2) 빌더가 `glass` 배치에 직접 넣는 삼각형을 가로채 같은 평면·맞닿은 것끼리 묶음(명동의 트레이서리 창, 성 베드로의 격자 창·랜턴·글로리아) (3) 사진 자리 `ctx.glassSlot`.
- 성당별 **어댑터**(`ADAPTERS`)가 좌표계와 구역·key 규칙을 갖는다. 성 베드로는 궁륭 채광창이 곡면을 따라 5줄로 나뉘어 있어 어댑터가 한 창으로 합친다(`mergeBy`).
- 공통 좌표계: **입구 +z, 제대 −z, 위 +y.** x 의 방위는 성당마다 다르다(각 절). x·y·z = 유리 평면 가운데(y 는 개구부 중심), `yaw` = atan2(nx, nz)(판의 +Z 가 실내를 봄, `glass_place.js buildMesh` 규약), 단위 앱 m.
- '지금 유리' 판정: 색 묶음의 채도·색상으로 `절차적 색유리` / `옅은 호박색(설화석고풍)` / `무색·옅은 유리` 를 가르고, 사진이 걸린 곳은 슬롯 이름을 적는다.
- 한계: 키트 창은 사양(벽 안쪽 면 기준)을 읽으므로 유리 평면 깊이(벽 두께의 절반 안쪽)는 반영하지 않는다(x·z 가 유리보다 0.1~0.3m 실내 쪽). 사진 판을 걸 때는 기존 `world.windowSlots()` 가 주는 깊이를 쓴다.

### 2.6 권리

- 1898년 창은 PD 로 본다(제작자 사후 70년 경과). 이남규의 보수분에 새 창작성이 있는지는 불명.
