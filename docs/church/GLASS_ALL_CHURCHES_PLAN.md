### 0.2 조회 스크립트 `tools/church_web/church_openings.mjs`

```
node tools/church_web/church_openings.mjs --all              # 일곱 성당 요약(개구부 수·구역·좌표계)
node tools/church_web/church_openings.mjs florence           # 개구부 전부(구역별, world 좌표·yaw·크기·형태·지금 유리)
node tools/church_web/church_openings.mjs florence --json    # 구현용 JSON
node tools/church_web/church_openings.mjs florence --md      # 이 문서의 표(같은 치수는 한 줄로 접음; 전부는 --md-full)
node tools/church_web/church_openings.mjs --check            # data/glass_windows/*.json 의 key·좌표가 지금 빌더와 맞는지
```

- `milan_openings.mjs` 와 같은 방식(가짜 canvas + vm)으로 빌더를 그대로 돌린다. 성당마다 창을 짓는 방법이 달라 **세 갈래**를 모은다: (1) 키트 창 `ctx.window`/`ctx.rose` 의 사양(`S_.windows`/`S_.roses`; 돔 드럼 창 포함) (2) 빌더가 `glass` 배치에 직접 넣는 삼각형을 가로채 같은 평면·맞닿은 것끼리 묶음(명동의 트레이서리 창, 성 베드로의 격자 창·랜턴·글로리아) (3) 사진 자리 `ctx.glassSlot`.
- 성당별 **어댑터**(`ADAPTERS`)가 좌표계와 구역·key 규칙을 갖는다. 성 베드로는 궁륭 채광창이 곡면을 따라 5줄로 나뉘어 있어 어댑터가 한 창으로 합친다(`mergeBy`).
- 공통 좌표계: **입구 +z, 제대 −z, 위 +y.** x 의 방위는 성당마다 다르다(각 절). x·y·z = 유리 평면 가운데(y 는 개구부 중심), `yaw` = atan2(nx, nz)(판의 +Z 가 실내를 봄, `glass_place.js buildMesh` 규약), 단위 앱 m.
- '지금 유리' 판정: 색 묶음의 채도·색상으로 `절차적 색유리` / `옅은 호박색(설화석고풍)` / `무색·옅은 유리` 를 가르고, 사진이 걸린 곳은 슬롯 이름을 적는다.
- 한계: 키트 창은 사양(벽 안쪽 면 기준)을 읽으므로 유리 평면 깊이(벽 두께의 절반 안쪽)는 반영하지 않는다(x·z 가 유리보다 0.1~0.3m 실내 쪽). 사진 판을 걸 때는 기존 `world.windowSlots()` 가 주는 깊이를 쓴다.

## 10. 사용자에게 물을 것 (기준이 이미 정해졌으므로 최소한)

1. **CC BY-SA 사진을 받아들일지.** 받아들이면 피렌체 측랑 4창이 전부 진본으로 해결된다(Sailko, CC BY-SA 4.0, 창 전체 약 1900×6200px). 지금 규칙은 CC0/PD/CC BY 만 허용이다(`GLASS_REFERENCES.md`).
2. **'순서 추정' 창을 성당 안에 걸어도 되는지**(밀라노 익랑 8창과 같은 처리). 피렌체 27곳(드럼 6면, 정면 측면 2, 측랑 4, 경당 15)과 명동 후진의 장면 배열이 해당한다. 안 된다면 이들은 QA 갤러리에만 두고 성당 안에는 확정된 2곳(이미 걸린 진본)만 남는다.
3. **피렌체 트리부나 윗창 15개를 뚫을지**(실제 창이고 벽도 있으나, 창턱 높이 근거가 없고 빌더 수정이 필요하다).
4. **실제로 그림 유리가 아닌 창의 색을 빼도 되는지**: 피렌체 신랑 고창 8·측랑 1·2칸 4·드럼 서 1, 라테라노 후진 4. 실제에 맞지만 실내 분위기(색빛)가 줄어든다.
5. **우리 본당**: 방안 가(추상 색면 + 상징) / 나(신비 장면) / 다(지금 유지) 중 무엇으로 할지, 그리고 그 창작 그림을 배포판에 넣을지.
6. **저작권이 살아 있는 두 창**(명동 이남규 1989, 마조레 하이날 1995): 자리를 뚫고 색조 패널만 걸지, 자리 자체를 만들지 않을지.

## 11. 직접 열지 못한 출처 · 한계

- **피렌체**: `duomofirenze.it/en/cupola-vetrate-cori/`(봇 확인 화면) · it.wikipedia "Vetrate di Santa Maria del Fiore"(문서 없음) · Temple 대학 학위논문(403) · `duomo.firenze.it` 의 「성모 승천」 설명(검색 결과로만). 그래서 **드럼 6면의 배치, 정면 측면 오큘러스의 좌우, 트리부나 경당의 순서**가 미확정이다. ICCD 기록의 번호 체계(1~15, A = 윗창 / B = 경당 창으로 보임)를 끝까지 풀면 경당 순서를 확정할 수 있을 것이다(43건의 본문을 모두 정독하지는 못했다).
- **명동**: 나무위키 시설물 문서(403) · KCI 논문 본문(초록만) · 공식 사이트의 유리화 안내(찾지 못함). 15단의 창별 배열, 측랑·고측창의 개수·무늬, 정면 장미창의 존재가 미확정이다. 익랑 두 창의 좌우는 개인 글 한 곳에 의존한다.
- **로마**: 그림 유리가 "없다"는 것은 기록을 찾지 못했다는 뜻이다. 창을 하나하나 확인하지 않았다. 마조레 후진 창의 수·형태, 정면 안쪽 벽의 다른 창은 확인하지 못했다. vatican.va 의 대성전 안내는 새 사이트로 넘어가 해당 문장을 읽지 못했다.
- 위키미디어 공용 API 는 요청 제한(429)이 잦아 범주 4개(피렌체 2, 명동 실내, 라테라노 후진)와 파일 62건의 라이선스만 확인했다. 썸네일(330~640px)로 내용을 확인한 사진은 13장이다(피렌체 6, 명동 5, 라테라노 2). **텍스처로 쓸 원본은 하나도 내려받지 않았다**(조달은 구현 단계에서, 라이선스를 다시 확인하고).
- Google Arts & Culture 는 권리 표시가 있는 이미지라 열람·수집하지 않았다.
- 스크립트의 키트 창 좌표는 벽 안쪽 면 기준 사양이다(§0.2 한계). 화면 캡처로 대조하지 않았다.
- 권리 항목은 위험 표시일 뿐 법률 검토가 아니다.

```
node tools/church_web/church_openings.mjs --all          # 요약
```

- ICCD 기록: `https://sigecweb.beniculturali.it/sigec/item/print/ICCD<번호>`(PDF). 피렌체 창은 13663940~13663991 사이에 있다.
