# 외부 UX 검토(ChatGPT) 기록과 우리 계획에의 반영

작성일: 2026-11-12 · 관련: `UX_PLAN.md`(R1~R3), `PRAYER_REDESIGN.md`(기도·성당 통합), `GLASS_APP_PLAN.md`, 관리자 콘솔 로드맵(`ROADMAP_ADMIN.md`)

## 1. 이 문서의 성격과 한계

- 외부 도구(ChatGPT)가 앱을 대상으로 한 UX 검토다. 검토는 **13개 시나리오(S1~S13)** 로 이뤄졌고, 발견 사항, 점수 기준(루브릭), 사용자 시험 계획, 확인 질문 5개를 냈다.
- 이 기록은 검토 내용을 요약해 전달받은 것을 그대로 옮긴 것이다. **시나리오 S1~S13 의 개별 문안과 루브릭 점수표 원문은 전달받지 못해 여기에 적지 않았다.** 지어내지 않는다. 원문을 확보하면 2장 앞에 덧붙인다.
- 검토자는 앱을 직접 실행하지 않고 설명·화면 자료에 근거했다. 그래서 검토의 사실 주장은 우리 코드·조사와 대조한 뒤에만 받아들인다(3장).
- 새로 생긴 과제는 `docs/ux/UX_REVIEW_ITEMS.json`(U-01~U-18)이 원본이고, 관리자 콘솔 로드맵의 '외부 UX 검토' 출처 칩으로 보인다.

## 3. 따르지 않기로 한 제안

| # | 검토 제안 | 결정 | 이유 |

| 1 | 첫 입장의 아바타 설정을 '방문객으로 입장'에 합쳐 없앤다. | 따르지 않음 | 소유자가 성별·머리·세례명을 **한 설정 화면에서 기본값이 채워진 채 직접 고르게** 하기를 명시적으로 원했다. 기본값이 채워져 있어 바로 확인만 눌러도 입장된다. |

## 5. 사용자 시험 계획 (U-18)

- **참가자**: 어르신 5명 + 청년 5명. 1인 45~55분.
- **과제 5개**
  1. 큰 글씨로 첫 기도 시작하기
  2. 지하철에서 한 단 바치기, 전화를 받은 뒤 이어서 바치기
  3. 잠자리에서 음성으로 기도하기
  4. 성 베드로 대성전 방문: 촛불 봉헌, 앉기, 큰 글씨, 돌아오기
  5. 기록 확인과 새 휴대폰으로 옮기기
- **성공 횟수는 실제로 센 값만 기록한다.** 시험 전에는 비워 둔다.

## 6. 검토가 던진 확인 질문 5개와 우리 답

| # | 질문 | 우리 답 |
|---|---|---|
| 1 | 한 단만 바친 기록의 기준은? | **아직 정하지 않았다.** 5단 완주와 구별되는 '한 단 완료' 기록이 필요하다(U-04). |
| 2 | 음성은 어떻게 구현했고 잠금화면에서 되나? | AI 음성 파일을 앱에 포함하고 기기 TTS 를 대체로 쓴다. **잠금화면 재생은 아직 없다.** 자동 진행이 생기면 포그라운드 미디어 서비스가 필요하다(P-05). |

| 4 | 저장 위치, 계정 연결, 병합 규칙은? | 기본은 기기 로컬 저장. 계정 연결은 구현했으나 **실제 Supabase 프로젝트에 대해서는 검증하지 않았다.** 병합 규칙은 현재 다른 사용자가 로그인하면 이 기기의 기록을 지우고, 양방향 병합은 없다. |
| 5 | 공유 성당에서 연결이 끊기면? | 같은 방의 사용자에게만 아바타·촛불이 보인다. 연결이 끊기면 혼자 모드로 떨어지고, 재연결하면 자리는 다시 배정된다. |

## 8. 2차 검토(화면 캡처 기반, 2026-11-13)와 현황 대조

1차와 달리 실제 화면 캡처를 보고 한 검토다. 소유자가 붙여 넣은 요약을 그대로 옮겼고, 원문 캡처는 전달받지 못했다. 과제는 `UX_REVIEW_ITEMS.json` 의 `round: 2` 항목(U-19~U-33)과 1차 과제의 `review2` 필드(보강 메모)가 원본이다. 관리자 콘솔에는 세 번째 마이그레이션(`20261115000000_roadmap_items_3.sql`)으로 들어간다. 소유자 결정이 필요한 과제는 메모가 `[결정 필요]`로 시작한다.

### 8.1 검토 요약

- **P0-1 기도문 큰 글씨(2배)**: 기본 글씨는 360×800dp 에서 성모송이 아멘까지 보이지만, 2배에서는 본문 아랫줄이 잘려 보이고 '↓ 9줄 더 (쪽 1/3)'과 '다음'이 함께 나와 '읽던 기도문의 뒷부분'과 '다음 구슬'이 헷갈린다.
- **P0-2 묵주 전체 보기**: '손대지 않으면 4초 뒤 닫힙니다' 자동 닫힘, 촘촘한 구슬, 누르면 바로 이동. 자동 닫힘 제거, '닫고 계속', 큰 이동 단추, 되돌리기, TalkBack 에서 시트 유지와 닫은 뒤 포커스 복귀를 요구.
- **P1**: 오늘 탭 첫 카드(오늘의 신비 + 기도 방식, 이어서 기도하기 + 구슬 위치, 한 단 바치기는 시작 버튼 아래) / 성당 첫 입장 간소화(기본 아바타 + [성당 들어가기], 외형은 '모습 바꾸기', 공개 세례명은 직접 고를 때만) / 성당 목록의 '실제의 40%'는 상세에서만 / HUD '가기' → '장소로 이동'·가까운 빈 자리·입구 카메라·정면 보기·이름표 거리별 축소 / 성당 좌석 기도 카드('기도문 크게 보기' 직접 표시, '성당 자리로 돌아가기', 공유 세션, 타이머 라벨 또는 내리기) / 촛불 봉헌(용어 통일, '마음속 지향으로', 성공 화면 '촛불을 밝혔습니다', 초기 미선택).
- **P2**: 기록 첫 화면은 최근 기도·달력 우선, 연속/최장 강조 축소 / 완료 화면 '묵주기도를 마쳤습니다 · 기록을 저장했습니다' / 계정 연결 시 '기록 지키기'·마지막 백업 상태.
- **검토자 스스로의 정정**: 1차의 본문 가림 수치는 360×640 결과라 360×800 에 적용할 수 없다. 장소 이동, 지향 선택, 기록 달력·최근 기록, 공식 서비스 안내는 **이미 있다**(새 기능이 아니라 배치·문구·피드백 개선). 착석 장면은 자세와 좌석 접점을 정면·측면에서 검증해야 한다.

### 8.3 P0-1 에서 고른 안: 독립 스크롤 영역 + 줄 맞춘 '기도문 계속 읽기'

검토는 두 길을 냈다. (가) 본문을 독립 스크롤 영역으로 두고 끝까지 읽게 한다. (나) 쪽 방식을 유지하되 이름을 구분하고 온전한 줄에서 끊는다. **(가)를 바탕으로 (나)의 두 조건을 함께 넣었다.**

- 쪽 번호('↓ 9줄 더 (쪽 1/3)')를 없앴다. 쪽 수는 '다음'과 나란히 있을 때 '무엇의 다음인가'를 흐리게 하는 정보였다. 대신 스크롤 막대(넘칠 때 늘 보임)와 위·아래 흐림이 '더 있음'과 지금 위치를 알린다. 손가락으로 밀면 끝까지 간다.
- 글 칸 바로 아래에 **'기도문 계속 읽기'**(테두리만 있는 작은 알약, 아래 화살표)를 둔다. 같은 기도문 안에서만 내리고 구슬은 바꾸지 않는다. 한 번에 내리는 거리는 **줄 경계**에 맞춘다: 아래에서 잘려 보이던 줄이 다음 화면의 첫 줄이 된다(건너뛰는 글 없음).
- 구슬 단추는 **'다음 구슬'**(채운 큰 단추, 하단 76dp 칸)로 이름을 바꿨다. 마지막 기도에서는 '기도 마치기'. 경계선 아래 따로 있어 자리·모양·색·이름이 모두 다르고, 끝까지 읽지 않아도 늘 누를 수 있다.
- 글을 짧게 누를 때: 읽지 않은 글이 남아 있으면 글이 내려가고, 끝까지 읽었으면(또는 넘치지 않으면) 다음 구슬. `PRAYER_REDESIGN.md` 원칙 1 그대로다. **바뀐 점**: 전에는 넘친 상태에서도 글을 누르면 바로 다음 구슬이었다.
- 3장 2번('↓ n줄 더' 알약을 없애지 않는다)의 취지는 그대로다. 기도문이 소리 없이 잘리지 않게 하는 장치는 남았고, 이름과 모양만 바꿨다.

### 8.4 P0-2 에서 바꾼 것

- 4초 자동 닫힘과 그 안내 문구를 없앴다. [닫고 계속], 끌어내리기, 뒤로 가기, 바깥 누르기로만 닫힌다.
- 큰 단추(48dp 이상): [처음]·[1단]~[5단](그 단의 처음), [되돌리기](직전 자리, 20번까지 거슬러 감), [기도하던 자리로](시트를 연 자리), [닫고 계속](52dp).
- '현재 위치  3단 성모송 2번째 구슬' 한 줄(화면 읽기 liveRegion). 단 단추는 'N단 처음으로', 기도하던 자리 단추는 자리 이름까지 읽는다.
- 닫으면 포커스(화면 읽기 포커스 요청 포함)가 연 단추(구슬 띠 또는 ⋮)로 돌아온다. 시트 글자는 시스템 글자 배율 1.3까지만 따른다. 내용은 SafeArea 안에 있다.
