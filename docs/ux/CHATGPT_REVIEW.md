# 외부 UX 검토(ChatGPT) 기록과 우리 계획에의 반영

작성일: 2026-11-12 · 관련: `UX_PLAN.md`(R1~R3), `PRAYER_REDESIGN.md`(기도·성당 통합), `GLASS_APP_PLAN.md`, 관리자 콘솔 로드맵(`ROADMAP_ADMIN.md`)

## 1. 이 문서의 성격과 한계

- 외부 도구(ChatGPT)가 앱을 대상으로 한 UX 검토다. 검토는 **13개 시나리오(S1~S13)** 로 이뤄졌고, 발견 사항, 점수 기준(루브릭), 사용자 시험 계획, 확인 질문 5개를 냈다.
- 이 기록은 검토 내용을 요약해 전달받은 것을 그대로 옮긴 것이다. **시나리오 S1~S13 의 개별 문안과 루브릭 점수표 원문은 전달받지 못해 여기에 적지 않았다.** 지어내지 않는다. 원문을 확보하면 2장 앞에 덧붙인다.
- 검토자는 앱을 직접 실행하지 않고 설명·화면 자료에 근거했다. 그래서 검토의 사실 주장은 우리 코드·조사와 대조한 뒤에만 받아들인다(3장).
- 새로 생긴 과제는 `docs/ux/UX_REVIEW_ITEMS.json`(U-01~U-18)이 원본이고, 관리자 콘솔 로드맵의 '외부 UX 검토' 출처 칩으로 보인다.

`우리 상태`: **이미 해결**(코드에 반영됨) · **설계됨**(문서에 설계가 있고 구현 전) · **신규**(이번에 새 과제로 추가).

## 3. 따르지 않기로 한 제안

| # | 검토 제안 | 결정 | 이유 |
|---|---|---|---|
| 1 | 첫 입장의 아바타 설정을 '방문객으로 입장'에 합쳐 없앤다. | 따르지 않음 | 소유자가 성별·머리·세례명을 **한 설정 화면에서 기본값이 채워진 채 직접 고르게** 하기를 명시적으로 원했다. 기본값이 채워져 있어 바로 확인만 눌러도 입장된다. |
| 2 | 기도문 아래 '↓ n줄 더' 넘침 알약을 없앤다. | 따르지 않음 | 기도문이 소리 없이 잘리지 않게 하는 장치라 유지한다(A-01의 핵심). |
| 3 | InPeace 에는 3D 성당 이동이 없다고 주장한다. | 근거 부족으로 받아들이지 않음 | 우리 조사(`survey/online_temple.md` 3) InPeace)에서 명동성당 모티브의 3D 공유 성당(촛불 봉헌, 묵주, 성호, 15개 언어)으로 확인했다. 이 부분의 검토 근거는 제한적이라 본다. |

## 4. 대비 제안값 (검토자 제안, 계산 확인)

아래는 **검토가 제안한 값**이고 우리 색이 아니다. 비율은 WCAG 2.x 상대 휘도로 다시 계산해 일치함을 확인했다. 감사(U-16)는 우리 실제 색(`lib/app/theme.dart` 시드 기반 ColorScheme, 성당 HUD)에 같은 계산을 적용하는 것이다. 기존 `test/theme_contrast_test.dart` 가 이미 일부 쌍(텍스트 4.5:1, 윤곽선 3:1)을 검사한다.

| 쌍 | 제안 색 | 비율 | 비고 |
|---|---|---|---|
| 본문 / 배경 | `#252019` / `#FFF8ED` | 15.3:1 | |
| 보조 글씨 / 배경 | `#65574A` / `#FFF8ED` | 6.6:1 | |
| 주 버튼 글씨 / 버튼 | `#FFFFFF` / `#803D2F` | 8.0:1 | |
| 아이콘·윤곽선 / 배경 | `#8A7464` / `#FFF8ED` | 4.18:1 | 작은 글씨에는 쓰지 말고 더 진한 색을 쓴다(4.5 미달) |
| 밤 모드 본문 / 배경 | `#F5E9DB` / `#201B18` | 14.3:1 | |

적용 원칙: 3D 장면 위의 HUD 는 반투명 위에 글씨를 얹지 않고 **불투명 면**에 올린다. 동작 줄이기 설정을 지킨다(U-17). 구슬 띠는 TalkBack 에 요약 한 줄만 읽힌다(U-03).

## 5. 사용자 시험 계획 (U-18)

- **참가자**: 어르신 5명 + 청년 5명. 1인 45~55분.
- **과제 5개**
  1. 큰 글씨로 첫 기도 시작하기
  2. 지하철에서 한 단 바치기, 전화를 받은 뒤 이어서 바치기
  3. 잠자리에서 음성으로 기도하기
  4. 성 베드로 대성전 방문: 촛불 봉헌, 앉기, 큰 글씨, 돌아오기
  5. 기록 확인과 새 휴대폰으로 옮기기
- **성공 횟수는 실제로 센 값만 기록한다.** 시험 전에는 비워 둔다.

| # | 지표 | 기준 |
|---|---|---|
| 1 | 첫 기도까지 시간 | 중앙값 30초 이하, 어르신 5명 중 4명이 60초 이하 |
| 2 | 완주율 | +10%p |
| 3 | 정확한 이어하기 | 20/20 (U-06, U-07) |
| 4 | 2분 안에 앉기 | 10명 중 8명 |
| 5 | 촛불 봉헌 성공 | 10명 중 9명, 중복 봉헌 0 |
| 6 | 큰 글씨 사용 | 사용률 기록 |
| 7 | 저사양 프레임 안정 | 간단 모드 p95 50ms 이하, 분당 250ms 초과 끊김 1회 이하 |
| 8 | 오프라인 핵심 경로 | 100% (U-08) |

## 6. 검토가 던진 확인 질문 5개와 우리 답

| # | 질문 | 우리 답 |
|---|---|---|
| 1 | 한 단만 바친 기록의 기준은? | **아직 정하지 않았다.** 5단 완주와 구별되는 '한 단 완료' 기록이 필요하다(U-04). |
| 2 | 음성은 어떻게 구현했고 잠금화면에서 되나? | AI 음성 파일을 앱에 포함하고 기기 TTS 를 대체로 쓴다. **잠금화면 재생은 아직 없다.** 자동 진행이 생기면 포그라운드 미디어 서비스가 필요하다(P-05). |
| 3 | 3D 자산, 최소 기기, 실측 FPS는? | three.js 와 자산을 앱에 포함한다. **실기기 FPS 실측은 아직 없다.** 측정 절차는 `docs/church/PERF.md`(C-04). |
| 4 | 저장 위치, 계정 연결, 병합 규칙은? | 기본은 기기 로컬 저장. 계정 연결은 구현했으나 **실제 Supabase 프로젝트에 대해서는 검증하지 않았다.** 병합 규칙은 현재 다른 사용자가 로그인하면 이 기기의 기록을 지우고, 양방향 병합은 없다. |
| 5 | 공유 성당에서 연결이 끊기면? | 같은 방의 사용자에게만 아바타·촛불이 보인다. 연결이 끊기면 혼자 모드로 떨어지고, 재연결하면 자리는 다시 배정된다. |
