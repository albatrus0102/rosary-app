# 묵주기도 앱 메뉴·UI/UX 개선 계획

작성일: 2026-11-12 · 대상: Android(Flutter) · 1인 개발, 빠른 반복 전제

**근거 자료**
- `[RA]` 묵주기도 앱 조사(rosary_apps.md), `[OP]` 온라인·소셜 기도 조사(online_prayer.md), `[OT]` 온라인 사찰 조사(online_temple.md), `[3D]` 3D·메타버스 기도 공간 조사(prayer_3d.md).
- 조사 자료의 근거 표기는 그대로 옮겼다. `[V]/[확인]/[S]`는 출처를 읽고 확인한 것, `[S]`(OP)/`[2차]`는 검색 요약이나 2차 자료, `[U]/[일반]/[B]`는 확인하지 못한 것, `[I]`는 조사자의 추론이다. 앱을 직접 설치해 써 본 조사자는 없다. 기능 설명은 대부분 스토어 문구다.
- 코드 근거는 `파일:줄` 형식이다(2026-11-12 기준 저장소).

## 1. 한눈에 보기

### 핵심 발견 5가지

1. **한국 묵주기도 앱 1위들의 가장 큰 불만은 '화면이 꺼지면 소리가 멈춤'과 '글씨가 작음'이다.** 바오로딸(100K+)과 굿뉴스 모두 화면 꺼짐 재생 불만이 있고, 매일미사·Pray with me는 글자 크기 불만이 있다 `[RA §1-13,14,15,20]`. 우리 앱은 지금 손으로 넘기는 방식이고 화면을 켜 둔다(`prayer_screen.dart:122`). 그래서 이 불만은 아직 생기지 않는다. 다만 소리로 이끄는 자동 진행을 넣는 순간 같은 문제가 생긴다. 신뢰성과 큰 글씨만 잘 해도 차별점이 된다.
2. **9일·54일 기도와 '빠진 날 용서'가 한국 특유의 재방문 장치다.** 바오로딸이 사랑받는 주된 이유가 56일 9일기도 달력이고, Righthand는 "하루 빠져도 끊기지 않는 54일"을 내세운다 `[RA §3-7]`. 굿뉴스 묵주기도는 기도일 수 초기화 버그로 비판받았다 `[OP §1.15, S]`. 우리 앱에는 이 기능이 없다.
3. **3D 공유 성소는 지금 한국에서 실제로 유행 중이고, 가톨릭 직접 경쟁작이 이미 있다.** 산사는 가입 없이 링크만 누르면 들어가고, 채팅 없이 '한 가지 동작'만 한다. 이 방식으로 1주일에 100만~150만 방문을 모았다 `[OT §1-1, 확인]`. 첫날 동시 접속 20석에서 서버가 죽었다 `[3D §1.1, S]`. 가톨릭 쪽에는 InPeace(명동 모티브, 촛불·묵주·세례명, 무가입)와 찬미(신자석, 봉헌초, 6·12·18시 삼종 종)가 있다 `[OT §1-3, 확인]` `[3D §1.1, S]`. InPeace에는 결혼식 놀이, 미니게임, 고해 체험이 함께 있다 `[OT §1-3, 확인/2차]`. 우리 앱의 강점은 '실제와 같은 8개 성당'과 '앉으면 바로 묵주기도'다. 약점은 진입 마찰이다. 지금은 로그인, 동의, 성당 고르기, 상세 시트, 아바타 편집을 모두 거쳐야 들어간다.
4. **세계 시장은 '소리로 이끄는 플레이어'와 '조용한 구슬 세기'로 갈라져 있고, 둘 다 잘하는 한국 앱은 없다** `[RA §5-1]`. 우리 앱은 혼자·선창·후창 모드, 번들 AI 선창 음성, 구슬별 진동을 이미 갖췄다. 두 방식을 모두 할 수 있는 바탕이 있는 셈이다.
5. **함께 기도하기는 '말 없는 공존'이 안전하고 잘 통한다.** Pray.com의 공개 피드는 사생활 사고를 냈다 `[OP §1.2, V]`. 산사·Sky는 채팅 없이도 "혼자이면서 함께"를 만들었다 `[OT §3-2]` `[3D §1.12]`. 소셜 쪽에서 가장 검증된 장치는 작은 고정 모임의 릴레이(Hozana의 5인 '살아있는 묵주', 50만+)다 `[RA §1-9]`. 우리 SPEC도 이미 자유 입력을 금지하고 세례명·지향을 프리셋으로만 받는다(`docs/church/SPEC.md §0`). 이 방향을 유지한다.

### 추천 포지셔닝 (3줄)

> **"오늘의 묵주기도를 가장 편하게, 그리고 실제 성당에서 함께."**
> 1) 광고 없음, 오프라인, 큰 글씨, 빠진 날을 탓하지 않는 9일·54일 기도. 매일 쓰는 개인 묵주기도 도구로서 바오로딸을 대체한다.
> 2) 실제 성당을 충실히 재현한 공간에서 말 없이 함께 앉아 묵주기도와 봉헌초를 바친다. 놀이·성사 흉내·공덕 점수는 없다(InPeace와의 차별점).

## 2. 현재 앱 진단

### 2.1 현재 정보구조(IA)

```
앱 실행
 ├─ [백엔드 빌드] 로그인(카카오/구글/이메일) ─ 동의(필수 3 + 선택 4) ─┐   auth_config.dart:6 requireLogin=true
 └──────────────────────────────────────────────────────────────┘
 하단 탭(app_shell.dart:103-114)
 ├─ 기도 (home)
 │   ├─ 이어서 기도하기 카드(7일 이내)
 │   ├─ 묵주 그림 카드 → '묵주' 탭으로 이동
 │   ├─ 기도 기록 요약 카드 → 기도 기록(stats) 화면
 │   ├─ 오늘의 신비 4장 + 선택한 신비 5단 목록
 │   ├─ 기도 모드: 혼자 / 선창 / 후창
 │   └─ [하단 고정] 기도 시작 → 기도 화면(전체 화면, push)
 ├─ 묵주 (rosary_styles)  묵주 모양 고르기만 있음
 ├─ 설정 (settings)
 │   ├─ 소리·진동 / 기도문 표시(글꼴·글자 크기·Material You)
 │   ├─ 선창 음성(AI 수녀님·신부님 / 기기 음성 / 직접 녹음)
 │   ├─ 계정·기록(계정, 기도 기록)
 │   └─ 정보(기도문 출처, 합성 음성 안내, 라이선스)
 └─ 성당 (church_select → church)
     ├─ 성당 고르기: 검색, 필터 칩, 카드 격자(일부 '준비 중'), 상세 시트 → 입장
     ├─ [첫 입장] 아바타 편집 강제
     └─ 3D 성당: 상단(이름·인원 칩, 소리, 아바타, 인사) · 조이스틱 · 앉기/초 켜기 · 기도 카드
```

## 3. 제안 메뉴·정보구조

### 3.1 새 상위 IA: **오늘 · 성당 · 기록 · 더보기** (탭 4개)

> 현재 구현(GLASS_APP_PLAN §2.1): 탭은 **성당(첫 탭·메인) · 오늘 · 기록 · 더보기**. 성당 탭 안에 `[성당 | 창]` 전환이 있고 '창'은 스테인드글라스 갤러리(보조)다. 아래 트리는 M-01 당시 초안이다.

```
오늘 (기본 탭)
 ├─ 이어서 기도하기 (있을 때만, 맨 위)
 ├─ 오늘의 신비 카드: 이름 · 5단 요약 · [바꾸기] · 전례 시기 표시
 ├─ 진행 중인 9일/54일 기도: "청원 12/27일째 · 오늘은 고통의 신비"
 ├─ 오늘 기도했어요 ✓ (실물 묵주로 바친 날도 1탭 기록)
 ├─ 다음 함께 기도 시간: "오후 9:00 명동대성당 함께 묵주기도"
 └─ [하단 고정] ▶ 고통의 신비 바치기 (기도 방식은 시작 전 준비 화면에서)
성당
 ├─ 마지막 성당 큰 카드: 이름 · "지금 N명 기도 중" · "오늘 켜진 초 N" · [입장]
 ├─ 다른 성당 고르기 (현재 고르기 화면, '준비 중'은 숨김)
 └─ 3D 성당
기록
 ├─ 달력(기도한 날) · 이번 달/올해/전체 (현재 stats 화면)
 ├─ 9일/54일 기도 (진행·지난 기도·보충한 날)
 └─ 내 지향 (기기 안에만 저장, 응답받음 표시)

 ├─ 알림(삼종 6·12·18시, 매일 묵주기도 시각)
```

**옮기는 것과 이유**
- '묵주' 탭은 **더보기 > 기도 화면 > 묵주 모양**으로 옮기고, 기도 화면의 보기 설정 시트에서도 바꿀 수 있게 한다. 꾸미기 기능이 탭 하나를 차지할 이유가 없다.
- '기도 모드(혼자/선창/후창)'는 홈에서 빼서 **기도 준비 화면**으로 옮긴다. 마지막 선택을 기억하므로 매번 고를 필요는 없다. 홈은 "무엇을 바칠지"만 보여 준다. 잘 평가받는 단일 목적 앱은 '오늘' 카드 하나로 바로 연다 `[RA §6]`.
- '기록'은 탭으로 올린다. 9일·54일 기도와 지향이 들어갈 자리가 필요하고, 매일 다시 열 이유가 되는 화면이다 `[RA §3-7, 3-9]`.
- '성당'은 둘째 탭이다. 앱의 차별점이므로 엄지가 닿기 쉬운 위치에 둔다. 다만 기본 탭은 '오늘'이다. 3D는 무겁고 매일 쓰는 기능이 아니기 때문이다.
- 별도 '기도' 탭(기도문 모음 등)은 만들지 않는다. 기능이 많아질수록 "찾을 수 없다"는 불만이 늘어난다 `[RA §4]`. 기도문 모음은 R3에서 '더보기'에 넣는다.

### 4.1 주요 결정과 이유

- **게스트 대 강제 로그인 → 게스트(익명 로그인)를 권한다.** 산사·InPeace·바오로딸·Righthand가 모두 무가입이고, 강제 로그인은 Hallow와 Click To Pray 불만의 중심이다 `[RA §4]`. Supabase 익명 로그인을 쓰면 실제 사용자 행(`auth.users`)이 생긴다. 그래서 지금의 RLS, `has_consent()`, 이벤트·동기화 구조를 그대로 쓸 수 있고, 나중에 카카오·구글을 연결해 같은 계정으로 승격하면 된다. 동의(필수 3 + 선택 4)는 그대로 받되 한 화면으로 줄인다. 분석은 동의한 게스트에게서도 모을 수 있다. 사용자의 목표인 '이용 행태 최대 파악'은 가입자 수가 아니라 동의율에 달려 있다. 게스트로 열면 측정 대상 사람 수가 오히려 늘어난다. 단, 기기를 바꾸거나 앱을 지우면 기록이 사라지므로 기록이 7일 이상 쌓이면 '기록 지키기(로그인 연결)'를 한 번 권한다.
- **'제한 없음'과 '빈 방'은 함께 지킬 수 있다.** 샤딩은 사용자에게 보이지 않게 한다(같은 성당에 다른 샤드 사람이 보이지 않을 뿐이고, 입장 거절은 없다). 인원수는 전 샤드 합계로 정확히 표시한다. 새로 들어온 사람은 앉은 사람이 많은 샤드와 구역에 먼저 배치한다. 사용자 결정(SPEC §15)을 어기지 않는다.
- **사실감은 유지하고, 저사양 기기는 간단 모드로 받는다.** 사실감을 낮추는 대신 앉은 고정 시점, 30fps, 렌더링 생략으로 비용을 줄인다. 앉으면 카메라가 고정되므로 화질을 유지한 채 부하만 크게 줄일 수 있다.
- **소셜은 프리셋으로만 한다.** 이름은 세례명 목록, 지향은 프리셋, 인사는 동작, 촛불 동참은 1탭이다. 자유 입력이 없으면 신고할 거리도 거의 없다. SO-01은 '보기 싫은 사람 숨기기'가 주 목적이다.

## 7. 열린 질문 (사용자 결정 필요)

| # | 질문 | 권장 기본값 |
|---|---|---|
| Q1 | 로그인 필수를 유지할까, 게스트(익명 로그인)로 시작하게 할까? | **게스트로 시작.** 같은 서버 구조(익명 사용자)로 분석·동의를 그대로 유지하고, 7일 기록 뒤 '기록 지키기'로 연결을 권한다. |
| Q2 | 54일 기도에 빛의 신비를 넣을까? | 시작할 때 고르게 하고, **기본은 '네 가지 신비 순환'**으로 한다. 전통 방식(환희·고통·영광)도 선택지로 둔다(한국 앱들이 둘 다 지원 `[RA §1-13,18]`). |
| Q3 | 성당에 자유 입력(닉네임·채팅)을 앞으로 넣을까? | **넣지 않는다.** 세례명 목록, 프리셋 지향, 동작만 쓴다. 신고 처리 운영을 1인이 감당할 수 없다. |
| Q4 | 명동대성당 등 한국 실존 성당 모형을 그대로 둘까? | 유지하되 "공식 서비스 아님" 고지를 넣고, 홍보 전 서울·전주·대구 교구 홍보 담당에게 알리고 의견을 묻는다. |
| Q5 | 후원(기부)을 넣을까? | **R3까지 넣지 않는다.** 넣더라도 '더보기 > 앱 후원' 한 곳에서 1회 후원만. 기도·성당 안에는 넣지 않는다. |
| Q6 | 알림 기본값을 켤까? | **꺼짐.** 첫 완주 화면에서 "매일 이 시간에 알려 드릴까요?"를 한 번 묻는다. 소리는 무음 알림이 기본이다. |
| Q7 | '소리로 이끌기'를 AI 음성으로 할까, 사람 녹음을 구할까? | 지금의 AI 음성(고지 포함)으로 시작한다. 본당 성가대나 수도회 녹음 협조를 R3 과제로 둔다(사람 목소리 선호 `[RA §1-5,13]`). |
| Q8 | 저사양 기기에서 3D 대신 간단 모드를 자동으로 보여 줄까? | 첫 입장 5초 동안 평균 15fps 아래이면 "간단 모드로 바꿀까요?"를 **묻는다**(강제 전환 없음). 사실감을 우선하는 사용자 결정을 존중한다. |
