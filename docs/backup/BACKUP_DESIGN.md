# 백업과 복원 — 설계·상태×사건 표 (2026-11-16)

> 목표: 사용자가 기도 기록과 설정을 **절대 잃지 않는다**. 독서공방(reading-journal)의 검증된 백업 설계
> (exportData·importDataText·plainDB·자동 백업 SAF·금고·안내 카드)를 Flutter/Dart + 안드로이드 플랫폼 채널로 옮겼다.
> 코드: `lib/backup/`, 네이티브 `android/app/src/main/kotlin/kr/rosary/rosary_app/BackupBridge.kt`·`BackupShareProvider.kt`,
> 안드로이드 자동 백업 규칙 `android/app/src/main/res/xml/{data_extraction_rules,backup_rules}.xml`.

실패로 알린다. 등록부에 `backup`(값 모양) 또는 `exclude`(이유) 한 줄을 더하면 끝 — 실행 중에는 등록되지 않은 키도
비밀처럼 보이지 않으면(token·secret·session·pkce·api key…) 일반 수집으로 실린다(등록을 잊어도 값이 빠지지 않게).

## 2. 파일 형식(세 통로가 같은 한 벌)

```json
{"format":"rosarium-backup","schemaVersion":1,"minReaderSchema":1,"appVersion":"0.1.0+1",
 "createdAt":"…Z","device":{"platform":"android","source":"export"},
 "summary":{"prayerRecords":12,"settings":30},
 "data":{"prefs":{"chime_ten":{"t":"bool","v":true}},"prayerRecords":[…],"…모르는 구역…":{}}}
```
- 수동 내보내기(`rosarium-export-YYYYMMDD.json`)·자동 백업 폴더(`rosarium-backup-YYYYMMDD-HHmmss.json`)·기기 안 금고가
  모두 `BackupCollector.collect`(저장소에 **실제로 쓰인 것**)로 만든다.
- 판 올리기(`BackupMigrations`)는 **필드를 더하기만** 하고 깊은 사본 위에서 돈다(한 단계가 던지면 원본은 그대로, 파일은 거부).
- 앞으로의 호환: 새 판 파일도 `minReaderSchema`가 지금 판 이하면 읽는다. 모르는 `data` 구역은 `backup.carry_v1`에 보관했다가
  다음 내보내기에 그대로 싣는다. 모르는 설정 키는 비밀이 아니면 이 기기에 써 둔다(앱을 올리면 살아난다).
  읽을 수 없는 판이면 「앱을 업데이트한 뒤 다시 가져와 주세요」로 거부한다.
- 한도: 파일 2천만 자, 설정 2천 개, 키 200자, 글 100KB, 목록 1천 개(항목 500자), 기록 5만 개(id 64자), 보관 구역 1MB.
  한도를 넘은 칸·모양이 틀린 칸만 건너뛰고(미리보기에 개수가 보인다), 구조가 망가졌으면 통째로 거부한다.

## 3. 가져오기·되살리기 — 같은 문 하나(`BackupService.applyPlan`)

1. 읽기·검증·판 올리기 → **계획(미리보기)**: 더할 기록 n · 건너뛸 중복 m · 바뀔 설정(이름) · 건너뛸 칸 · 보관 한도 초과.
2. 사람이 「가져오기」를 눌러야만 진행.
3. **안전 사본**(금고 `pre0`, 2개 고리)을 쓰고 다시 읽어 확인 — 실패하면 아무것도 바꾸지 않는다.
4. 설정은 파일의 값으로 바꾼다(파일에 **없는** 설정은 건드리지 않는다), 이 기기의 같은 키가 다른 모양이면 건너뛴다.
5. 기록은 합친다(id·내용 지문). 지금 기록은 하나도 지우지 않는다.
6. `AppSettings.reloadFromPrefs()`·십자가의 길 선택 다시 읽기 → 금고에 새 상태 사본.

## 4. 자동 백업(SAF 폴더)

- 켜기 = 폴더 고르기까지 한 흐름. 폴더를 고르지 않으면 꺼진 채(「켜짐인데 폴더 없음」 상태를 만들지 않는다).
- 확인 시점: 열 때·돌아올 때(바뀌었고 24시간 지났으면 새 날 파일), 떠날 때(바뀌었으면 그날 파일을 새로 쓰고 하루 한 파일로 정리).
  바뀐 게 없으면 쓰지 않는다(내용 지문). 같은 때 두 번 돌지 않는다.
- 쓰기: 임시 이름 `….part.json` → fsync → `renameDocument`(못 하면 최종 이름으로 바로). 실패하면 방금 만든 문서만 지운다.
- 정리: 우리 이름 형식 + 실제 달력 날짜를 통과한 파일만, 하루 한 파일·최근 7일 치. 미래 이름은 가장 오래된 것으로,
  방금 쓴 파일은 절대 안 지운다. 수동 내보내기·사용자의 다른 파일·디렉터리는 대상이 아니다(Dart·Kotlin 양쪽 가드).
- 쓰기 직전마다 폴더를 다시 잰다: `ok · never · no_perm:p<n> · read_only · gone · no_create · err:<예외>`.
  「켜 두었는데 폴더를 못 씀」은 꺼짐으로 보이고 「잃음(한 번 성공했었음)」/「아직 안 고름(재설치·복원)」을 갈라 안내한다.
- **빈 기기는 폴더의 진짜 백업을 밀어내지 않는다**: 기록 0·설정 3개 이하인데 폴더 최신 백업에 기록이 있으면 쓰지 않고
  「이 폴더에서 백업을 찾았어요 — 되살릴까요?」를 띄운다. 금고가 「기록이 줄었어요」를 묻는 동안에도 쓰지 않는다.
- 끄면 폴더 권한을 놓아준다. 폴더의 파일은 그대로(앱을 지워도 남는다).

## 5. 기기 안 금고(`files/backup_vault`)

- 설정·기록이 바뀌면 2초 묶어(최대 10초) 사본 `g0`, 직전 `g1`, 날이 바뀌면 `d1`. 떠날 때는 바로. 바뀐 게 없으면 쓰지 않는다.
- 실행 때 먼저 `launchCheck`(이게 끝나야 쓰기가 열린다 — 새 설치에 돌아온 금고를 빈 상태로 밀어내지 않게):
  기록이 30% 넘게 + 5건 이상 줄었거나 있던 기록이 0, 또는 설정이 통째로 0 → 줄기 전 사본을 `guard`에 고정하고 묻는다.
- 사용자가 일부러 줄인 것(기록 지우기·계정 전환·계정 삭제 — 모두 `PrayerStatsStore.clear()`)은 `backup.vault.intent_drop_at` 표식으로 가른다.
- 추천 후보: 가장 많은 기록의 70% 이상 중 가장 최근(줄어든 사본은 추천하지 않음), guard는 다른 후보가 없을 때만. **늘 사람이 고른다.**
- 「이대로 둘게요」는 제안만 닫고 사본은 지우지 않는다. 계정 삭제 때는 금고를 모두 지운다.
- 안드로이드 자동 백업(구글 계정)·기기 이전은 이 폴더(와 녹음 폴더)**만** 담는다 → 앱을 지웠다 깔거나 폰을 바꾸면 금고가 돌아오고
  첫 실행에 「이 기기에 남아 있던 기록을 찾았어요」로 묻는다. 토큰·기기 id·동의 기록은 구글 드라이브로도 가지 않는다.

## 6. 안내(막지 않는다, 늘 닫을 수 있다)

| 종류 | 조건 | 닫으면 |
|---|---|---|
| 자동 백업이 멈췄어요 | 켜 두었는데 폴더를 못 씀(기록 수 무관) | 하루 |
| 기도 기록을 지켜 두세요 | 기록 3개 이상 · 백업 한 번도 없음 | 7일 |
| 자동 백업이 안 되고 있어요 | 켜짐 · 실패 1회 이상 · 마지막 성공 3일 넘음 | 7일 |
| 백업한 지 오래됐어요 | 자동 꺼짐 · 마지막 백업 14일 넘음 | 7일 |
| 한 달에 한 번, 파일로도 | 기록 10개 이상 · 파일 저장 30일 넘음(자동 켜짐이어도) | 30일 |

시계 되돌림 막기: 지금보다 1시간 넘게 미래인 시각(마지막 백업·닫은 때·마지막 성공)은 믿지 않는다 — 안 보면 그 미래까지 백업·안내가 멈춘다.

| S-25 | 저장 공간 가득 | 가져오기 | 안전 사본 실패 → 아무것도 바꾸지 않음 | vault「안전 사본을 못 쓰면」 |

| S-27 | 같은 기기 동시 편집 | 금고 쓰기 도중 또 저장·떠남 | 금고 쓰기는 한 줄로 세워 차례로(세대가 엇갈리지 않음), 늦은 쪽이 새 지문으로 한 번 더 | vault「동시에 불러도」 |
| S-28 | 「이대로 둘게요」 | 재실행 | 같은 줄어듦은 다시 묻지 않음, 사본은 남음 | vault「이대로 둘게요」 |

## 8. 독서공방에서 가져온 교훈(적용한 것)

- plainDB 원칙: 토큰·비밀·기기 고유 값은 백업 밖 — 등록부 + 비밀 모양 안전망 + 가져올 때도 무시(양방향).
- 세 통로(내보내기·자동 백업·금고)가 같은 묶음(B5).
- 금고에는 디스크에 실제로 쓰인 것만(B-12) — 저장소에서 읽어 만든다.
- 복원 후보는 내용으로 고른다(색인 파일 없음, 사본 안에 순번·시각, B-3).
- guard는 사람 확인 없이 고르지 않는다(B-1), 일부러 줄인 것은 표식으로(_intentDrop).
- 「되돌릴 수 있어요」는 사본 쓰기 성공을 확인한 뒤에만(B2), 고른 사본을 먼저 읽고 그 뒤 고리를 민다(B3).
- 판 올리기는 사본 위에서, 던지면 반쯤 바뀐 값을 쓰지 않는다(B4) · 필드 추가만 · 옛 앱/새 파일 호환(모르는 것 보관, 판 확인 + 분명한 문구).
- SAF: 임시 이름 → fsync → 이름 바꾸기(B-13), 반쪽 파일 물러나기(B-14), 미래 이름(B-15), 정리는 우리 이름만·디렉터리 제외·방금 쓴 파일 보호, 정리 실패가 쓰기 결과를 바꾸지 않음.
- 폴더 상태 사유 코드로 권한 회수·삭제·재설치를 가른다(autoBackupProbe/FolderState), 「켜짐 = 폴더까지」 한 흐름(가장 흔한 현장 실패 `no_folder`), 끄면 권한 반납.
- 안드로이드 자동 백업은 `<include>`만(exclude 없음, 끝 슬래시 없음) — 2026-08-20 빈 백업 세트 사고.
- 시계 되돌림(H11): 1시간 넘게 미래인 시각은 믿지 않는다.
- 데이터 경로에서 오류를 조용히 삼키지 않는다: 사유 코드를 남기고(debugPrint·상태 칸) 화면(설정 상태 줄·안내 카드)에 보인다.
- 사용자 값 보존 불변식: 등록부의 모든 backup 키가 왕복 시험을 받고, 못 받는 키는 UNCOVERED에 이유와 함께(지금 0).

## 9. 실기기에서 아직 재지 않은 것

- SAF 폴더 선택·권한 회수·폴더 삭제·드라이브 폴더(네트워크)에서의 실제 동작, `renameDocument` 미지원 공급자.
- 안드로이드 자동 백업 규칙의 실제 왕복: `bmgr` 로컬 트랜스포트로 `backupnow` → 지우기 → 재설치 뒤 `files/backup_vault`가
  돌아왔는지(독서공방 §6 절차 — 「Success」 신호는 판정이 아니다). 끝나면 트랜스포트를 구글로 되돌릴 것.
- 공유 시트(`BackupShareProvider`)로 드라이브·메일에 보내기.
